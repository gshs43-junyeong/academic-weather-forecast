# Forecast Loop · 랄프톤 키트 (사람용 사용 설명서)

본선 입력은 세 가지다. 셋 다 코드가 아니다(규정상 제한은 코드 사전 작성뿐, 이미지·영상 애셋은 자유).

| 입력 | 역할 |
|---|---|
| **SPEC.md** (별도 파일) | 기획·명세 전체: 기능과 완료 조건, 부하 지수·가중치, 데모 데이터(실제 학사일정·입시 일정), 디자인, 배경 영상, 기술 조건 |
| **PROMPT.md** (별도 파일) | 메인 에이전트에게 붙여 넣는 작업 지시: 규칙, 시작 순서, 반복 절차, 2차 루프, PROGRESS.md 양식 |
| **이 키트** | 스킬·서브에이전트·애셋 |

**데스크톱 전용. 평가 대상은 핵심 기능이다.** 1차 루프는 MVP 1~3을 만든다. 2차 루프는 실패 수정 → MVP 4~5 → 데모 확인까지가 본 작업이고, 배경 영상과 디자인 다듬기는 남는 시간에 한다.

## 키트 구성
| 위치 | 내용 |
|---|---|
| .claude/skills | 스킬 4개: coding-loop · weather-design · weather-animation · ui-tone(프로젝트 스킬로 자동 인식) |
| .claude/agents | 서브에이전트 3개(모두 Opus): inspector · design-reviewer · data-designer |
| assets/weather | 날씨 아이콘 애니메이션(WebP 투명·GIF 흰 배경). preview.gif는 비교용 |
| assets/video | 배경 영상: bg-main(실사 숲) + bg-sunny·cloudy·rain·storm(같은 풍경), 각 MP4·WebM·포스터. source·preview는 참고용 |
| docs | 제출한 참가 신청서·계획서(hwpx) |

※ .claude는 숨김 폴더다. 압축을 풀 때 함께 들어갔는지 꼭 확인한다.

## 본선 절차
| 시각 | 사람이 할 일 |
|---|---|
| 19:00 | 메인 저장소를 클론하고 루트에 키트를 푼다(.claude 포함, 빈 README.md는 이 설명서로 덮어씀). 같은 위치에 SPEC.md와 PROMPT.md를 둔다. 커밋해서 main에 푸시한다. |
| 19:05 | 저장소 폴더에서 Claude Code를 실행한다. 메인 모델을 **Fable**로 고르고, "어떤 스킬과 에이전트가 있어?"로 스킬 4개·에이전트 3개가 인식되는지 확인한다. ultracode를 쓸 경우 하위 에이전트가 Opus로 도는지 `/workflows`에서 확인한다. |
| 19:15 | PROMPT.md 내용을 통째로 붙여 넣는다. 1차 루프가 시작된다(상한 1시간). |
| 첫 푸시 직후 | Vercel에서 이 저장소를 가져와 main 브랜치 자동 배포를 연결한다(설정은 기본값). 배포 링크를 팀원에게 공유한다. |
| 루프 중 | 에이전트가 상한 전에 멈추면 "계속"이라고 입력한다. 노트북을 만지면 가재탈을 착용하고 PROGRESS.md "사람 개입 기록"에 시간·이유·한 일을 적는다. |
| 20:15 | 1차 루프 종료. 팀원이 배포 링크를 노트북 브라우저로 열어 PROGRESS 체크리스트를 눈으로 확인한다. 고칠 점은 "사람 개입 기록"에 적는다. SPEC.md를 바꿔야 하면 사람이 직접 수정한다. |
| 20:35 | "2차 루프 시작"이라고 입력한다(상한 30분). |
| 21:05 | 새 기능 금지. 기능 실패가 남았으면 그것부터 처리한다. 기능이 다 통과했을 때만 "design-reviewer로 채점하고 점수 낮은 3개만 고쳐"라고 지시한다. |
| 21:35 | 다른 기기로 배포 링크에 접속해 데모 전체 단계를 돌리고, 체험 완료 코드를 확인한 뒤 링크를 제출한다. |

## 막혔을 때
- Fable을 고를 수 없으면 메인도 Opus로 하고, 나머지는 그대로 둔다.
- 영상이 끊기면 "배경 영상 대신 포스터 이미지를 쓰게 바꿔"라고 지시한다.
