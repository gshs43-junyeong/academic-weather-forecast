# 학업 기상청 — 코딩·루프 운영 지침

## 기준 문서
- 운영 절차는 PROMPT.md(시작 순서·반복 절차·2차 루프·PROGRESS.md 양식)를 따른다.
- **SPEC.md가 유일한 기준**이다(기획·명세 문서). 완료 조건은 1장, 부하 지수·가중치·테스트는 2장, 데모 데이터는 3장, 디자인은 4장, 배경 영상은 5장.
- 이 스킬과 SPEC.md가 다르면 SPEC.md를 따른다.

## 우선순위
- 평가 대상은 사이트의 핵심 기능(SPEC.md 1장 MVP)이다. 기능 조건이 남아 있는 동안에는 배경 영상 적용이나 디자인 다듬기를 하지 않는다.
- 날씨 아이콘 이미지는 MVP 1에 필요한 만큼 1차부터 쓴다. 키트의 이미지·영상은 자유롭게 써도 된다(규정 제한은 코드 사전 작성뿐).

## 모델과 역할
- 메인 에이전트는 Claude Fable로 실행한다. 구현과 커밋·푸시만 한다.
- 서브에이전트는 예외 없이 Claude Opus로 실행한다: 검수관(완료 조건·테스트·스크린샷 판정), 디자인 리뷰어(SPEC.md 4-7 체크리스트 채점), 데이터 설계자(데모 데이터 조건 계산 확인).
- 메인은 자기 작업을 스스로 통과 처리하지 않는다. 통과 판정은 검수관이 한다.

## 시간 상한
- 1차 루프(메인 구현): 최대 1시간. 2차 루프(수정): 최대 30분.
- 상한에 닿으면 진행 중인 조건을 PROGRESS.md "중단"에 적고 즉시 멈춘다. 상한 이후 새 기능 시작 금지.

## 루프 규칙
1. 매 반복 시작 시 SPEC.md와 PROGRESS.md를 읽는다. PROGRESS.md가 없으면 SPEC.md 1장의 완료 조건을 체크리스트로 옮겨 만든다.
2. 체크되지 않은 조건 중 번호가 가장 앞선 것 하나만 처리한다.
3. 계산 로직은 테스트를 먼저 쓴다. 테스트와 빌드가 모두 통과해야 검수관에게 넘긴다.
4. 화면 조건은 검수관이 브라우저 자동화로 장면을 열어 확인하고, 스크린샷 경로를 PROGRESS.md에 남긴다.
5. 같은 조건에서 3번 연속 실패하면 "막힘"에 원인을 적고 다음 조건으로 넘어간다.
6. 통과한 조건마다 커밋하고 **곧바로 GitHub main 브랜치로 푸시**한다(Vercel 자동 배포). 커밋 메시지는 조건 번호로 시작. 테스트·빌드가 깨진 상태로는 절대 푸시하지 않는다.
7. SPEC.md는 수정하지 않는다. 모호하면 PROGRESS.md "질문"에 적는다.
8. PROGRESS.md "사람 개입 기록"에 적힌 지시가 가장 우선이다.

## 금지
- 외부 API를 호출하지 않는다. 서버 함수·API 키 없이 브라우저 안에서만 동작하는 정적 사이트로 배포한다.
- 실제 학생 이름·학번 없이 가상 데이터만 쓴다.
- 로그인, 서버 DB, 푸시 알림, NEIS 연동은 만들지 않는다.
- 제공된 날씨 아이콘 이미지와 배경 영상을 수정하거나 다시 생성하지 않는다.

## 기술 방향
- 언어는 HTML · TypeScript · CSS. Vite로 구성하고 프레임워크는 쓰지 않는다. 타입 오류는 빌드 실패로 본다. 막히면 해당 파일만 JS로 써도 되지만 계산·해석 모듈은 TypeScript를 유지한다.
- 스타일은 일반 CSS 파일에 디자인 변수를 한 곳에 모아 참조한다.
- **Rust(WebAssembly)는 신중하게**: 기본은 쓰지 않는다. 계산 모듈이 실제로 느려(재계산 0.5초 초과) 완료 조건을 못 지킬 때만 검토한다. 쓸 경우 Vercel 빌드 환경에 Rust 도구가 없으므로 미리 빌드한 결과물을 저장소에 넣어야 하고, 같은 계산의 TypeScript 버전과 결과가 일치하는 테스트를 반드시 둔다. 시간 상한 안에 끝낼 자신이 없으면 쓰지 않는다.
- 차트는 라이브러리 없이 SVG로 직접 그려 아이콘·카드와 같은 색을 쓴다. 타임라인 드래그는 포인터 이벤트로.
- 계산 모듈은 화면 코드와 분리하고 화면 요소에 접근하지 않는다(테스트 가능하게).
- 단위 테스트 도구와 브라우저 자동화 도구로 데모 7단계를 검증한다.
- 저장은 브라우저 저장소를 쓰되 실패해도 가상 데이터로 동작하게 감싼다.
- 공지문 해석은 규칙 기반 모듈(계산 모듈처럼 화면과 분리). 규칙과 샘플 정답은 SPEC.md 2-4.
- 폴더는 계산 · 공지문 해석 · 가상 데이터 · 화면 · 공개 애셋으로 나눈다. 날씨 아이콘은 공개 폴더의 weather, 배경 영상은 공개 폴더의 video에 둔다(START.md 1단계에서 키트 assets에서 복사). 키트의 assets·docs 폴더와 영상 source·preview 파일은 배포 결과물에 넣지 않는다.
